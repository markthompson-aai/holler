# Holler in detail

The [README](../README.md) covers what most people need. This page is the full reference: exactly what each request and action does, and every check Holler makes before it touches an agent.

## Using Holler

The hotkey is right ⌥ unless `HOLLER_HOTKEY` names another.

- **Hold the hotkey** and speak. A pill appears top-right while you talk and while Holler works, and grows into the note when there's something to read.
- **Hold again** to ask a follow-up in the same conversation. You can also cut in while Holler is still transcribing or thinking: hold the hotkey and the request in progress is dropped, along with any card it was about to show, and Holler listens again. A quick tap closes the note instead, and a shortcut that uses the hotkey, like ⌥3, leaves the request running.
- **Tap the hotkey** to close the note, whatever Holler is doing: a tap while it transcribes or thinks drops that request too. Holler still remembers the conversation, so a minute later you can ask "is it done yet?" without saying which agent. It forgets after 20 minutes without a request, when you quit, or when you choose **Menu bar › New Conversation**, which also closes the note. Closing the note drops any card still waiting, unsent.
- **Return** confirms the newest waiting card, whose button shows **↩**. While a card waits, the note has the keyboard, so Return goes to Holler and never to your terminal. Press any other key to give the keyboard back to the app you were in; that key is lost, and the card waits for a click. The next card takes the keyboard again. Once no card is waiting, the keyboard goes back on its own.
- **Esc** closes the note, dropping its cards, only while Holler has the keyboard like this: while a card waits or counts down and you haven't pressed another key. At any other time Holler leaves Esc alone, because it can't keep the key from the app you're in, where the same Esc would interrupt a working agent. That includes while Holler listens, transcribes or thinks, and a countdown once you've taken the keyboard back: tap the hotkey to close the note then.
- **Corrections replace their card.** "Actually, tell it to open the PR as a draft" drops the waiting card it corrects, unsent, and shows the new one. "And also tell it to run the tests" adds a second card instead.
- **Messages to agents** show as a card. Nothing is sent until you click **Send** or press **Return**.
- **Answers are read aloud**, in AssemblyAI's Anna voice (the Mac's as fallback), while **Menu bar › Read Answers Aloud** is on, which it is until you switch it off; Holler remembers it. Say "just show me" or "write me a summary" to keep one answer silent, and with the setting off, "read me the summary" or "talk me through the api agent" speaks one. Brief by default (the counts, then each agent that needs you), detailed when you ask for more, and an explanation in full. Cards, countdowns and alerts are never spoken. Holding the hotkey or closing the note stops the voice, and VoiceOver stays quiet while Holler speaks.
- **Menu bar › Run Simple Actions Without a Card** (off until you turn it on; Holler remembers it) lets a message to an idle agent, and a new agent in a new tab, go after a countdown instead: the card reads "Sending in 3… 2… 1…" (or "Starting in"), then it runs. **Return** runs it at once; **Cancel**, **Esc** or closing the note stops it, and nothing is sent or started; any other key gives the keyboard back while it counts, and Esc goes back to your app with it, so from then on stop the countdown with **Cancel** or a tap of the hotkey. Holding the hotkey to speak pauses it ("Paused for your follow-up") until Holler answers: "actually, say this instead" replaces it, so the old one is never sent and the new one counts down from 3, while anything else, or a request that fails, lets it carry on from where it stopped. Several actions from one request count down together, each with its own Cancel. At the end each is checked again: if the agent has started working, or gone, or the workspace has closed, the card waits for you as usual. Say "show me first" or "don't send it yet" to keep the card for one request. Closing a tab, interrupting an agent, starting one in a worktree, and a message to a working agent always wait for you. So does a message or first task that starts with `!` or `/`, which Claude Code and Codex run as a shell command or a slash command rather than read; its card warns you ("Starts with !, so the agent runs it as a shell command rather than reading it."). With the setting on, a message or start that waits says why in a quiet line on its card ("api is working, so this waits for you.").
- **New agents** show as a card too: workspace, tab name, folder and first task. Nothing starts until you click **Start** or press **Return**, or, with Run Simple Actions Without a Card on, until its countdown ends. Holler then opens a tab, starts the agent in it and gives it the task. It starts Claude unless you ask for Codex ("start a Codex agent in the web project to…"), and the card names which one. The first time Claude runs in a folder it asks whether to trust it. Holler leaves that question for you to answer in the new tab, so trust the folders you use first.
- **Starting in a worktree** ("start Claude in a worktree of the web project to try the cache fix") gives the agent its own git checkout on a new branch named after the tab, so parallel attempts don't collide. Herdr makes the worktree (`herdr worktree create`) in its worktrees folder (`[worktrees] directory` in Herdr's config, `~/.herdr/worktrees` by default), as `<repo>/<branch>`, and opens it as its own workspace named after the tab, not a tab in the workspace you named. The card shows the checkout's path, the branch and that workspace. Claude asks whether to trust each new checkout, so expect that question in the new workspace. If Herdr doesn't trust the repository, Holler tells you why and leaves trusting it to you in Herdr; it never passes `--trust-repository` itself. Closing the agent's tab later doesn't delete the checkout or the branch.
- **Closing a tab** ("close the dark-mode tab") works only for tabs Holler started, even after Holler restarts, as long as the agent it started is still running in the tab. The card shows the tab, each agent's state and its last line of output, and warns you if an agent is working or waiting on you. Nothing closes until you click **Close** or press **Return**. Holler refuses any other tab.
- **Interrupting an agent** ("stop the api agent") sends a working agent Esc, as if you pressed it in its terminal: it stops what it's doing and waits at its prompt, and its tab stays open. It works on any agent Holler can see, not only ones it started. The card shows the agent and its last line of output, and nothing is sent until you click **Interrupt** or press **Return**. Holler only interrupts an agent that is working: if it has finished, or is waiting on you, by the time you confirm, nothing is sent and the card says why.
- **Jumping to an agent** ("show me the api agent", "take me to the one that needs me") switches Herdr to that agent's tab and pane, brings its terminal to the front and closes the note. It only moves your view, so there's no card. If more than one agent fits, Holler asks which. If a card is still waiting, Holler switches the tab but keeps the note open and doesn't bring the terminal forward, so Return still goes to the card. You can also **click an agent's row** in a summary to jump to it; if the agent has gone, or two agents share its name, the note says so and stays open.
- **"What's changed since I last asked?"** lists the agents that changed since your last request, in any conversation: status changes with their times, agents that started or closed, and what's new on the screens of agents still working. Summaries say how long each agent that needs you has waited ("Waiting 12 min."), longest first.
- **The note opens the moment you let go of the key**, with a row per agent: its name, whether it needs you, is working or idle, and how long it has been so ("Waiting 12 min."). The rows come from Herdr straight away and keep up with its events while Holler works, so you can see who needs you before the answer is in; the answer then takes their place. A follow-up in an open note shows the earlier answer instead.
- **"Tell me when the api agent finishes"** sets an alert: when that agent stops working, whether it finishes, ends by asking you something or its tab closes, a quiet note appears on its own saying so, under the words you used, with nothing spoken. If the note is already open, the line joins it. The alert keeps until it fires or you quit Holler, even after the note closes or the conversation is forgotten, and a follow-up right after ("what did it do?") carries on from it. One alert per agent; an agent that isn't working when you ask is reported the next time it stops.
- **Menu bar › Reopen Last Note** shows the last note's requests and answers again, while Holler still remembers that conversation. Its cards never come back: closing the note is how you drop a waiting card, so the note says where one was instead.
- **Menu bar › Type a Question…** asks without speaking, for meetings or a shared office. If the note is open, it's a follow-up there.
- **Menu bar › Summarise My Agents** asks without the mic. Handy when the room is noisy.

## How Holler reads your agents

The first request of a conversation includes what's on every agent's screen (up to 3k characters each), so a summary needs one model call. Follow-ups include it only for the agents the conversation has been about, plus any whose status changed or that just appeared; the model reads any other agent, or further back, on demand. Holler reads the screens as soon as you let go of the key, while your words are still being transcribed, and only the screen, since Herdr reads scrollback many times slower. A request that only queues cards ends on them, without a second model call to say they're ready. Agents that are working can only be read from the visible screen; Herdr refuses scrollback reads while an agent is busy.

Names travel with the screens. Every request gives LLM Gateway the agent list: each agent's workspace and tab names, its folder's path, its status and its terminal title, plus each workspace's tabs and folders. Each press gives the Dictation API the workspace, tab and folder names as key terms, so an agent's name is heard right. Only agents Holler can see are named, in both.

Holler follows Herdr's event stream (`events.subscribe` on Herdr's socket) to time each agent: when it started working, and when it stopped and began waiting on you. Herdr doesn't timestamp states, so Holler only knows waits since it started watching; an agent that was already waiting shows "at least". Each request still takes a fresh Herdr snapshot, which also catches up on anything the stream missed. If the stream drops or Herdr's socket can't be reached, Holler reconnects in the background and carries on from snapshots alone, timing a change when it notices it. What it has seen is kept in `~/Library/Application Support/Holler/herdr-history.json` (the last 500 changes, each agent's status and when it changed, and where you last asked), so after a relaunch wait times and "what changed since I last asked" carry on from where they were. A pane whose terminal id has changed, as after a Herdr restart, counts as a new agent rather than the old one. Holler also keeps each agent's screen as it last showed it to the model, so a follow-up reads the agents still working and sends only the lines that are new since then.

## Safety model

- **No shell.** The model never gets one. It can call eight tools: `list_agents`, `read_agents`, `focus_agent`, `prompt_agent`, `start_agent`, `close_tab`, `interrupt_agent` and `tell_me_when`. Read aloud isn't a tool: the spoken version comes back in the same reply as the note.
- **Messages wait for you.** `prompt_agent` only queues a message. It reaches the agent only after you confirm it, or, once you've allowed simple actions to run without a card, after a 3-second countdown you didn't cancel, at the end of which the agent is looked up again in a fresh snapshot and must still be the same agent, and idle. Either way it goes through `herdr agent prompt <pane> <text>` run as literal arguments with no shell. The text is typed at the agent's prompt, so what it can do is whatever the agent does with it. A message that starts with `!` or `/` is one the agent runs, as a shell command or a slash command, rather than reads: it never counts down, and its card carries a warning. The same goes for a new agent's first task.
- **New agents wait for you too.** `start_agent` only queues a start. It runs only after you confirm it, or, once you've allowed simple actions to run without a card and it isn't in a worktree, after a 3-second countdown you didn't cancel. At the end of the countdown the workspace must still be open and allowed in a fresh snapshot. Either way, as it starts, the workspace and folder are checked again: the workspace must still be open and allowed, and the folder must exist and not be excluded, symlinks included. Only Claude or Codex can be started, with their normal permissions. A worktree start also checks the new checkout's path against the exclusions before anything is made, symlinks included, and again where Herdr says it put it. Holler refuses a repository with an excluded folder inside it, since a worktree would copy that folder somewhere Holler can see, and a worktree whose workspace the workspace filter would hide.
- **Holler only closes tabs it started.** `close_tab` only queues a close, and only for a tab Holler opened; any other tab is refused, even in an allowed workspace. Holler saves the tabs it starts in `~/Library/Application Support/Holler/started-tabs.json`, each with its pane, its agent's session id and Herdr's terminal id. Herdr starts tab ids over when it restarts, so a saved id alone could point at someone else's tab: a tab only counts as Holler's while the agent Holler started (same pane, and the same session and terminal ids that were saved) is still in it. Herdr reports no session for Codex, or for Claude while it asks whether to trust the folder; then the tab is saved by its terminal id alone, which starts with the time the terminal opened and so doesn't repeat after Herdr restarts. A tab with neither id isn't saved, and Holler can't close it. When you confirm, the tab is looked up again in a fresh Herdr snapshot and refused if it has closed, wasn't started by Holler, or has any pane in an excluded folder or workspace. Herdr closes a tab whatever its agents are doing, so the card warns you when one is working or waiting on you.
- **Interrupts only reach working agents.** `interrupt_agent` only queues an interrupt. When you confirm, the pane is looked up again in a fresh Herdr snapshot and must still hold the agent on the card (the same terminal, tab and kind of agent), and it must still be working; then Holler runs `herdr agent send-keys <pane> esc`. Esc is never sent to an agent waiting on you, where it would dismiss its approval or question.
- **Jumps only move your view.** `focus_agent` runs straight away, with no card, because it sends nothing to the agent: it runs `herdr agent focus <pane>`, which also clears a finished agent's Done badge. The pane is looked up in a fresh Herdr snapshot first, so a hidden or unknown agent can't be focused.
- **Alerts only watch.** `tell_me_when` sends nothing to the agent. It runs straight away, with no card, and only asks Holler to show a quiet note when that agent stops working.
- **Panes are checked before anything is sent.** When you confirm, and at the end of a countdown, the target pane is looked up again in a fresh Herdr snapshot. A closed, made-up or excluded pane is rejected. So is one that no longer holds the agent on the card: Herdr starts its pane ids over when it restarts, so the same id can come to name someone else's agent. Holler compares the pane's terminal id, which doesn't repeat, along with its tab and the names of its workspace and tab; if any has changed, nothing is sent and the card says why.
- **Events are only listened to.** The only socket call Holler makes is `events.subscribe`, for the agents the filters allow plus panes and tabs opening and closing.
- **Approvals stay with you.** Holler never sends a message to a blocked agent, i.e. one waiting on an approval or a question: it checks the agent's status in a fresh snapshot before it sends, and Herdr refuses such a message too. So Holler can never approve anything for you.
- **Terminal output is treated as untrusted data**, never as instructions.
- **Secrets are redacted before pane text leaves the Mac, as far as Holler can recognise them.** Before screens, terminal titles and tab names go to LLM Gateway, Holler replaces each of these with a marker such as `[redacted key]`, keeping the line count so line references still hold:
  - private key blocks;
  - `NAME=value`, `NAME: value` and `"name": "value"`, where the name contains key, token, secret or password;
  - secrets given to a command: `--password …`, `--token …`, `--api-key …`, `curl -u user:password` and `mysql -pPASSWORD`;
  - passwords in connection strings (`scheme://user:password@host`);
  - `Bearer` and `Authorization: Basic` credentials, and JWTs;
  - keys and tokens with a known prefix: OpenAI and Anthropic (`sk-`), Stripe (`sk_live_`, `rk_live_`), Google (`AIza`), AWS access key ids (`AKIA`, `ASIA`), GitHub (`ghp_`, `github_pat_` and the like), GitLab (`glpat-`), Slack (`xox…-`, `xapp-`), npm (`npm_`) and Hugging Face (`hf_`);
  - a 32-character hex string on its own, which is what an AssemblyAI key looks like.

  When one of these runs to the right edge of the screen and wraps, the rest of it on the next row is replaced too. This is a best-effort net, not a guarantee: a secret in any other shape, such as a bare AWS secret key or a password printed with nothing to mark it, is sent as it is. `HOLLER_EXCLUDE_PATHS` is the control to rely on for a folder whose screens must never leave the Mac.
- **You can keep folders private.** `HOLLER_EXCLUDE_PATHS` hides the panes of agents working in the folders you list, so they are never read or sent anything. Write each folder as an absolute path, or starting with `~` or `$HOME`. Upper and lower case don't matter and symlinks are followed, so a folder is hidden however it's spelled. A tab with any pane in a hidden folder isn't named to the model either. A change to this setting or to `HOLLER_WORKSPACES` takes effect as soon as the settings reload: Holler closes the note and starts a new conversation, so nothing it remembers about an agent you've just hidden is sent again. `Holler --check` lists the folders in force, and an entry that hides nothing, because it isn't an absolute path or the folder doesn't exist, is logged under the `Settings` category and fails the check.
- **You can limit it to one workspace.** `HOLLER_WORKSPACES` does the same for every workspace not on the list. It limits what Holler sees, not where a new agent may work: in a workspace on the list, Holler can start an agent in any folder that isn't excluded.
